# 共通用語集（どのプロジェクトでも通じる言い回しの正本）

この頁は**プロジェクトをまたいで共有する**。ここに無い語・ここと意味が違う語は、
各プロジェクトの `.claude/glossary.md` に書く（**固有が共通を上書きする**）。

⚠️同じ名前で中身が違う語をここに入れないこと。入れると別プロジェクトで説明が嘘になる。
⚠️このファイルは git に入らない。控えが各 repo の `.claude/glossary-shared.md` にある。

書式：`| 用語 | 平易な説明（1〜2文・専門語で説明しない） |`

## Hook・設定

| 用語 | 説明 |
|---|---|
| Hook | Claude Code が特定のタイミングで自動実行する外部コマンド。ツール呼び出しの前後、応答の終わりなどに差し込める |
| Stop hook | 応答が終わったときに走るHook。内容を見て「まだ足りない」と差し戻せる |
| stop_hook_active | 「すでに差し戻しの続きを走っている」ことを示す印。これを見ないと同じ指摘を無限に繰り返す |
## 頁で新しく拾った語（check_gloss.py の②が出したもの）

| 用語 | 説明 |
|---|---|
| Stop フック | 応答が終わったときに走るHook。内容を見て「まだ足りない」と差し戻せる |
| 指紋 | 応答の中身から作った短い符号。同じ中身なら同じ符号になるので「もう一度言おうとしている」ことが分かる |
| `transcript_path` | フックに渡される、会話の記録ファイルの場所。Claude Code も Codex も渡す（2026-08-23に訂正＝Codexは渡さないと書いていた） |
| `cwd` | いま作業しているフォルダの場所。本文も記録の場所も渡ってこなかったとき、記録を探す最後の手掛かりに使う |
| `hook_event_name` | どのきっかけで呼ばれたかを示す欄。Codex と Hermes はこの名前で送ってくる |
| `last_assistant_message` | 直前のアシスタント発話の本文そのもの。Codex の Stop はこれを渡すので、記録を読まずに済む |
| `pre_verify` | Hermes のフック。ファイルを直した回だけ「終わる直前」に走り、押し戻せる（Claude Code の Stop と同じ書式が通る） |
| `post_llm_call` | Hermes のフック。応答が出来上がった直後に本文ごと走るが、ここから同じターンを続けさせることはできない |
| `pre_llm_call` | Hermes のフック。モデルを呼ぶ直前に走り、context という欄を返すとユーザーの発言に文を足せる |
| `trusted_hash` | Codex がフックの設定を承認済みか見分けるための印。これが無い設定はファイルがあっても走らない |
| 許可リスト | Hermes が「このフックを走らせてよい」と覚えておく名簿。ここに無いフックは設定に書いてあっても走らない |
| `--accept-hooks` | Hermes を1回起動するときに付けると、未承認のフックをその場で名簿に載せる指定。対話の確認を省く代わりに、中身を自分で確かめた前提になる |
| `shlex` | 命令文を単語に割る仕組み。Windowsのバックスラッシュを食う（`C:\Users` が `C:Users` になる）ので path はスラッシュで書く |
| イベント（フックの） | フックが起動するきっかけ。例＝応答が終わった（Stop）／道具を呼ぶ前（pre_tool_call）／セッションが終わった（on_session_end） |
| 相対パス | いま居るフォルダを起点にした場所の書き方。起点が動くと同じ文字列が別の場所を指す |
| 非ブロッキング扱い | フックが失敗しても応答を止めない扱い。安全側だが、失敗が沈黙になるので気づけない |
| 終了コード | プログラムが終わるときに返す番号。0が成功で、それ以外は失敗の種類を表す |
| 構造の重さ | 表の行・見出し・箇条書きの本数を足した数。文字数が伸びなくても画面が長い応答を拾うために数える |
| `CLAUDE_PROJECT_DIR` | Claude Code がフックに渡す、プロジェクトの根っこのフォルダの場所。相対パスの代わりにこれを使えば作業フォルダが動いても壊れない |
| `PYTHONUTF8` | Pythonに文字の扱いをUTF-8で固定させる指定。Windowsの既定(cp932)では日本語が壊れる |
