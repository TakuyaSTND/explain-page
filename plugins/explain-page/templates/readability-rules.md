# 読みやすさ規則（正本）

説明フック（`.claude/hooks/visual/entrypoint.py` → `readability.py`）が使う、
**使ってはいけない言い回し**（否定側）の正本。用語集（`.claude/glossary.md` 等）が
「正しい言い回し」を機械で照合するのに対し、こちらは逆向き＝「その言い回しは避ける」を拾う。

出所＝mathbullet/skills（MIT License, Copyright (c) 2026 mathbullet）
`ja-text-communication` の原則 B2・B4。ローカル参照先＝
利用者フォルダの `.claude/plugins/marketplaces/skills` の下の `ja-text-communication`
（`plugins/ja-text-communication/skills/ja-text-communication/SKILL.md`）。

> B2. 英単語に日本語助詞・活用を直接接続しない（「generic な」「retrieve した」などを禁止）。
> B4. 独自の造語・圧縮熟語を作らない。俗語・比喩・口語表現（「...に落とす」「...を流す」
>     「...を受ける」など）は、技術的な実体の言い換えを添えるか、使わない。

関門の状態＝`off`／`shadow`（数えて知らせるだけ）／`enforce`（差し戻す）。既定は`shadow`
（`.claude/visual-hook-policy.json` の `readability`）。新設はまず`shadow`で数え、
空振り（普通の日本語を誤って拾うこと）が無いと確かめてから`enforce`へ上げる。

## 機械規則

判定ロジック本体は `readability.py` が持つ（ここは説明のみ・表ではない）。

- **B2型＝英単語＋形容動詞化・動詞化・コピュラの直結**：小文字で始まる英単語（3字以上・
  全大文字の略語 `AI`/`PDF`/`HTML`/`URL`/`JSON`等は対象外・数字混じりも対象外）の直後に、
  空白0〜1個を挟んで「な」「する」「した」「して」「される」「できる」「です」「なら」が
  続き、その後が英字でないものを当たりとする。例＝`generic な`→当たり、
  `retrieve した`→当たり。`AIに`（略語）・`Workflow を`（助詞「を」は対象外＝名詞として
  の使用は普通）・`data`単独（語尾が続かない）は当たらない。
  英文の中でありふれた機能語（`for`/`the`/`and`/`is`/`at` 等）は、造語というより
  英文の一部として出てくる方が多いため、誤爆防止のため常に対象外にしている。
- コード片（`<code>`・`<pre>`・Markdownのバッククォート）の中身は対象外＝識別子・
  オプション名・変数名は言い回しの対象ではない（`strip_code` が先に除く）。
- ⚠️**格助詞「に」は対象にしていない**（2026-09-08・較正で判明）。当初は原則B2の文言
  どおり「に」も語尾候補に入れていたが、実頁171枚で掛けたところ89枚・399件中319件が
  `gitに`／`jsonに`／`pythonに`／`sessionに`／`masterに`のような**技術用語・固有名詞へ
  の普通の格助詞付け**（「Workflowを」の「を」と同じ、名詞としての普通の用法）だった。
  B2が狙うのは英単語を日本語の**形容動詞・動詞であるかのように**活用させる誤りなので、
  場所・対象を示すだけの「に」はここでは対象外にした。
- ⚠️**「な」は「など」「なので」「なのに」「なぜ」「なに」「なん」の頭とも重なる**。
  この続きが来た場合は当たりにしない（較正時に`decisionなど`を誤って拾った実例で発見）。

## 語リスト

B4（俗語・独自の造語）を単純な部分一致で拾う。「実務」のような普通の日本語は入れない
（誤爆の元）。10行以内で始める。

| 語 | 型 | 代わりの言い方 |
|---|---|---|
| に落とす | 俗語(B4) | 〜に整理する／〜の形にする |
| を流す | 俗語(B4) | 〜を実行する／〜を送る |
| 白箱 | AI由来の造語 | 中身が見える仕組み（意味を都度説明するか、普通の言葉に置き換える） |
| 軟正 | AI由来の造語 | ゆるやかに正しい・完全ではないが妥当（意味を都度説明するか、普通の言葉に置き換える） |

⚠️初期案には「を受ける」もB4俗語として入れていたが、2026-09-08の較正で外した。
「受ける」は「批判を受ける」「影響を受ける」のような**ごく標準の動詞**（受け取る、の意）
であり、実頁171枚で当たった28件は全て標準用法で、俗語（比喩・圧縮表現）ではなかった。
単純な部分一致では標準用法と区別できないため、単純一致の語リストからは外した。

### enforce に上げない判断（2026-08-28時点）

- 頁側の精度は十分。**止めているのは Stop 側**＝差し戻し判定に使う応答本文が、長い転写では**古いターンの断片**になる（実測＝18.1MBの転写で72字・現在ターンの語を含まない）。この状態で enforce にすると、古い応答の当たりで**現在の応答が差し戻され続ける**。
- ∴ enforce は「応答本文の取得を転写の**末尾**から行う」直しが入ってから。免除判定用の末尾読み（adapters の tail 読み）を応答本文にも使えば足りる見込み。判断は設計者（Hermes）へ。
- 自己言及の扱い＝規則を説明する頁は、例を `code` 書きにすれば対象外になる（code の中は除外）。enforce 前に**「例は code に書く」を規約に足す**。
- 副産物＝「〜に落とす」は私の書き癖そのもの。shadow の注記が出た時点で言い換える。
